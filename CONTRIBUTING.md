# Участие в разработке

Начинайте с небольшого изменения, которое можно отдельно понять и проверить. Запуск описан в [README](README.md), текущая работа — в [Issues](https://github.com/Dmitryaf/trajectory-app/issues) и [Project](https://github.com/users/Dmitryaf/projects/1).

## Найти место изменения

От видимого текста, обработчика или маршрута проследите путь к `src/features/`, store и владельцу сохранения. Карта зависимостей, сценариев и тестов находится в [ARCHITECTURE](docs/development/ARCHITECTURE.md). Для изменения текста прочитайте [PRODUCT_RULES](docs/product/PRODUCT_RULES.md), для данных — [ANALYTICS_DATA_CONTRACT](docs/product/ANALYTICS_DATA_CONTRACT.md).

Coding agents начинают с корневого [AGENTS.md](AGENTS.md). Общие инструкции AI Rules Hub и проектные контракты не дублируются в новых локальных framework-документах.

## Подготовить изменение

- Выбирайте задачу по актуальным Issues/Project и проверьте отсутствие дублирующего PR.
- Сохраняйте один понятный результат; несвязанный рефакторинг отделяется.
- Проверяйте изменённое поведение и значимые отказы. Для модели, sync и auth отдельно учитывайте совместимость и потерю данных.
- Выполняйте проверки по типу изменения из [PROJECT_RULES](.ai-rules/PROJECT_RULES.md); повторяющиеся UI-регрессии описаны в [QUALITY](docs/development/QUALITY.md).
- В PR объясните результат, выполненные проверки и ограничения. Порядок веток и поставки — в [DELIVERY](docs/operations/DELIVERY.md).
- Сообщения коммитов — английские Conventional Commits, например `fix: preserve unsaved review input`.

## Публичная граница

Репозиторий публичный. Не добавляйте секреты, реальные записи, дампы, логи, письма пользователей, локальные пути и внутренние рабочие или исследовательские заметки. Для примеров используйте синтетические данные. Размещайте документ в Git только при практической пользе пользователю, разработчику или оператору текущей системы.

Результат проверки хранится в Issue/PR с подходящей видимостью, история — в Git. Жизненный цикл личных данных описан в [DATA_GOVERNANCE](docs/operations/DATA_GOVERNANCE.md). Об уязвимостях сообщайте по [SECURITY](SECURITY.md), не в публичной задаче.
