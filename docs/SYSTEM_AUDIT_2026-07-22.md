# Аудит системы — 22 июля 2026

## Итог

Текущая версия пригодна для дальнейшей разработки: проверенные пользовательские сценарии работают, production-сборка воспроизводится, известных уязвимостей в production-зависимостях не найдено, а текущая схема Supabase ограничивает снимок владельцем записи через RLS.

Архитектура не является законченной слоистой системой. Это управляемый переходный монолит: страницы всё ещё напрямую координируют store, вычисления и браузерные действия, а общие `types.ts`, `analytics.ts` и `style.css` стали слишком крупными. Массовая перекладка файлов сейчас принесёт больше риска, чем пользы; разделение нужно продолжать вертикальными сценариями с тестами.

В ходе аудита исправлены два риска облачной синхронизации:

- одновременные реакции на восстановление сессии больше не запускают параллельную загрузку приложения;
- локальное изменение помечается ожидающим синхронизации до начала сетевого запроса, поэтому закрытие приложения или обрыв сети не создают ложный статус «синхронизировано».

## Что проверено

- модель и миграции ежедневных записей, итогов, событий, обзоров и настроек;
- IndexedDB, импорт/экспорт и стартовое согласование с облачной копией;
- авторизация Supabase и политики `trajectory_snapshots`;
- вычисления недели, месяца и трендов, особые дни и достаточность данных;
- прежние продуктовые исправления из заметок владельца;
- маршрутизация SPA, PWA-кэш, Vercel rewrites и восстановление после устаревшего чанка;
- автоматические тесты, Husky, commitlint и CI;
- границы слоёв, размеры исходных файлов и production-чанков;
- текущее дерево на отслеживаемые env-файлы и очевидные секреты;
- production-зависимости через `npm audit --omit=dev`.

## Найденные риски и приоритет

### P0 — выполнить до следующего production-релиза

1. **Граница импорта недостаточно строгая.** Версия и корневые массивы проверяются, но отдельные итоги и часть числовых полей не проходят полноценную нормализацию. Повреждённая ручная или облачная копия может попасть в runtime-модель. Следующая задача — ввести проверяемый нормализатор всего снимка до очистки IndexedDB и покрыть его ошибочными данными.
2. **Разделение сред не завершено внешне.** CI и правила описаны в репозитории, но branch protection, Vercel staging и отдельный Supabase нельзя подтвердить локально. До их настройки `develop` нельзя считать полноценной тестовой средой.

### P1 — ближайшие архитектурные срезы

1. Вынести стартовое согласование облака из `App.vue` в `features/sync`, оставив корневому компоненту только сборку приложения.
2. Разделить журнал целиком: фильтрация, пагинация и операции над записями сейчас повторяются в двух страницах.
3. Разделить `analytics.ts` по обзорам, наблюдениям, сравнению событий и покрытию данных. Общий файл превышает разумный объём одного контекста изменения.
4. Разделить `SettingsView.vue` по ежедневным блокам, пользовательским вариантам, эксперименту, облаку и резервным копиям.
5. Добавить браузерные проверки входа, восстановления из облака, конфликта версий, копирования и скачивания. Текущие 56 тестов в основном компонентные и модульные.
6. Защитить отдельным тестом отсутствие будущих точек графика веса.

### P2 — производительность и сопровождение

1. Production-сборка предупреждает о чанке ECharts около 618 КБ до gzip. Нужны измеримый бюджет сборки и проверка ленивой загрузки графиков; скрывать предупреждение повышением лимита нельзя.
2. `style.css` остаётся монолитом примерно на 65 КБ исходного CSS. Его стоит делить вслед за функциональными срезами, а не по произвольным категориям.
3. Storybook полезен для уже стабильных компонентов, но не заменяет сценарные и E2E-тесты. Начать с существующих полей, кнопок, карточек и граничных состояний.
4. В корне остаётся внутренняя инструкция `BACKEND_AUTH_CI.md`; перед публикацией она и ссылки на внутреннюю документацию должны исчезнуть из публичной истории.
5. В достижимой истории есть старый commit message с упоминанием Codex. Очистка истории остаётся отдельной разрушительной операцией только по явному разрешению.

## Состояние слоёв

```text
views  -> stores + services + features + shared types
stores -> IndexedDB + cloud infrastructure + normalization
features/export  -> чистый report + browser adapter
features/journal -> общий контрол диапазона дат
components -> в основном переиспользуемый UI
```

Положительная часть: чистая подготовка AI-отчёта отделена от Clipboard/Blob API, браузерные маршруты ленивые, база инкапсулирована store, а компоненты графиков не содержат продуктовых расчётов.

Нарушение целевой границы: `App.vue` и `SettingsView.vue` знают детали облачного протокола, страницы напрямую собирают аналитику, а store одновременно отвечает за состояние, персистентность и сетевую очередь. Это не блокирует приложение сегодня, но увеличит цену конструктора. Поэтому конструктор остаётся последним крупным изменением после стабилизации границ данных и функций.
