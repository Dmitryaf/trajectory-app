# Базовая проверка мобильной производительности

Проверка отвечает на два пользовательских вопроса: как быстро открывается установленная PWA и не загружает ли ежедневный экран тяжёлый код графиков до перехода в обзор месяца.

## Воспроизводимый профиль

- production-сборка из текущего commit;
- Chromium с размером экрана Pixel 5;
- задержка сети 150 мс, загрузка 1,6 Мбит/с, отдача 750 Кбит/с;
- замедление CPU в 4 раза;
- три независимых контекста браузера, решение принимается по медиане;
- команда: `npm.cmd run test:performance`.

Проверка измеряет первый и повторный запуск экрана «Сегодня», переход к заполненному обзору месяца и факт ленивой загрузки ECharts. JSON с отдельными прогонами, медианами и порогами прикладывается к результату Playwright.

Порог не следует увеличивать, чтобы скрыть регрессию. При падении сначала сравниваются отдельные прогоны и состав загруженных ресурсов, затем подтверждается проблема повторным измерением в том же профиле. Синтетический Chromium не заменяет проверку Safari/Chrome на физических устройствах перед публичным выпуском.

## Базовый результат 22 августа 2026

На локальной production-сборке медиана трёх прогонов составила:

- первый запуск «Сегодня» — 1 802 мс при пороге 6 000 мс;
- повторный запуск — 191 мс при пороге 3 000 мс;
- переход к заполненному месяцу и появление графика — 850 мс при пороге 5 000 мс.

Во всех трёх прогонах экран «Сегодня» не загружал ECharts, а обзор месяца загружал его только при переходе. Эти значения являются воспроизводимой локальной базой, но могут отличаться на физическом устройстве и в production-сети.
