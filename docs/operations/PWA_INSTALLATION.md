# Установка и проверка мобильной PWA

Документ предназначен владельцу проекта и тем, кто проверяет staging на физических устройствах. Короткая пользовательская инструкция не дублируется здесь: она доступна в приложении до входа в блоке «Установить на телефон» и после входа в `Настройки → Данные и синхронизация → Установка на телефон`.

## Перед проверкой

1. Использовать HTTPS-адрес staging и отдельный тестовый аккаунт без записей участников.
2. Записать commit сборки, модель устройства, версию ОС и браузера.
3. На домене проверить ответы `200` для `/`, `/manifest.webmanifest`, `/sw.js`, `/icons/icon-192.png`, `/icons/icon-512.png` и `/icons/icon-512-maskable.png`.
4. Не считать Playwright или режим эмуляции подтверждением физического устройства.

## Основной сценарий на каждой платформе

1. Открыть staging онлайн и войти в тестовый аккаунт.
2. Установить приложение по встроенной инструкции. На Android подтвердить браузерный prompt или установку из меню. На iOS использовать Safari: `Поделиться → На экран Домой`, включить «Открыть как веб-приложение» и нажать «Добавить».
3. Проверить значок, автоматический splash, отдельное окно без адресной строки и первый запуск.
4. На iOS дополнительно проверить portrait, landscape и отсутствие перекрытия safe areas.
5. Создать ежедневную запись и сохранить её. Полностью закрыть приложение, снова открыть по значку и проверить запись.
6. После успешного онлайн-запуска отключить сеть, полностью закрыть приложение и выполнить холодный запуск. Интерфейс и локальные данные должны открыться; недоступность облака должна быть показана как ожидаемая деградация.
7. Без сети изменить запись и сохранить её. Вернуть сеть, снова открыть приложение и убедиться, что облачная копия обновилась один раз, без дублирования данных.

## Сессия и обновление

На staging отдельно проверить три состояния Supabase:

- кэшированная действующая сессия открывает локальные записи и затем сверяется с облаком;
- истёкшая сессия восстанавливается через штатное обновление либо показывает вход, но не пустой рабочий экран;
- отозванная сессия возвращает ко входу и не показывает данные другого пользователя.

Для обновления service worker:

1. Открыть установленную сборку A и начать несохранённую ежедневную запись.
2. Опубликовать сборку B, не закрывая приложение.
3. Вернуть приложение на экран, затем выполнить свежий запуск.
4. Убедиться, что обновление не потеряло черновик, после сохранения используется сборка B, а старые чанки не приводят к пустому экрану.

## Удаление и ограничения

- Значок удаляется системной командой домашнего экрана. Удаление значка само по себе не является подтверждением удаления аккаунта, облачной копии или данных сайта; для этого используется раздел «Аккаунт и безопасность» и при необходимости очистка данных сайта в браузере.
- iOS сама формирует экран запуска и не гарантирует настраиваемый splash для каждой версии системы.
- Фоновая синхронизация не обещается. После офлайн-работы нужно вернуть сеть и открыть приложение.
- Persistent storage снижает риск автоматического вытеснения локальных данных, но не заменяет облачную копию и JSON-экспорт.
- Service worker обновляется по правилам браузера: свежий запуск должен получить новую версию, а уже открытое приложение не должно терять локальный черновик.

Актуальные системные шаги установки сверяются с [Apple Support](https://support.apple.com/guide/iphone/turn-a-website-into-an-app-iphea86e5236/ios) и [рекомендациями Chrome по PWA installation prompt](https://web.dev/learn/pwa/installation-prompt/).

Issue об установке можно закрывать только после заполнения обеих строк матрицы и прохождения всех сценариев на фактической staging-сборке.
