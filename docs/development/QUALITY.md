# Регрессионные контракты интерфейса

Памятка разработчику перед изменением компоновки «Траектории». Общие критерии качества задаёт AI Rules Hub, команды — [PROJECT_RULES](../../.ai-rules/PROJECT_RULES.md). Этот документ обновляется при появлении повторяющегося проектного класса регрессий.

## Общие механизмы и оставшаяся ручная граница

| Что меняется                           | Какой контракт сохранить                                                                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Условный блок или асинхронное действие | Интервал задаёт владелец раскладки. Проверяются предыдущий и следующий видимые соседи; появление сообщения, reset или индикатора не сдвигает соседние действия.                                                                       |
| Пагинация и замена списка              | Общие механизмы высоты и прокрутки сохраняют положение документа в обоих направлениях. Проверяются начальное, промежуточное и конечное состояние, а также `prefers-reduced-motion`; нельзя фиксировать только красивый конечный кадр. |
| Fixed-save и нижняя навигация          | Сохраняются место для последнего элемента и safe areas. Отдельно проверяются планшет, portrait/landscape и экранная клавиатура на устройстве: эмуляция не доказывает их поведение.                                                    |
| Фильтры и адаптивная сетка             | Обе стороны breakpoint и промежуточная ширина сохраняют читаемую ширину контролов и принадлежность подписей. Отсутствия горизонтального overflow недостаточно.                                                                        |
| Пользовательский текст                 | Непрерывная строка близко к лимиту и длинный placeholder не выталкивают действия. Используется общий `ClampedText`: раскрытие зависит от фактического overflow после изменения текста и размеров.                                     |
| Дата, время и десятичное число         | Нативные iOS-контролы ограничены шириной родителя; точка/запятая одинаково нормализуются для dirty-state и сохранения. Весь предусмотренный desktop-контрол открывает picker. Не теряется корневой `-webkit-text-size-adjust: 100%`.  |
| Модальное окно                         | Общий диалог закрывается по backdrop только при начале и окончании pointer-последовательности на нём. Перетаскивание изнутри наружу не закрывает окно; сохраняются блокировка scroll, `Escape`, удержание и возврат фокуса.           |

Реализованные геометрические сценарии находятся в [responsive-layout.e2e.ts](../../e2e/responsive-layout.e2e.ts) и используют [layout-assertions.ts](../../e2e/layout-assertions.ts). Логику переполнения отдельно защищает [ClampedText.test.ts](../../src/shared/ui/content/__tests__/ClampedText.test.ts). До локального обхода проверьте общий механизм и его потребителей.

Для существенного изменения плотности достаточно сначала проверить основной и насыщенный данными экран, затем расширять применение по результату. Визуальный эталон использует фиксированные данные, viewport, фокус, прокрутку и раскрытие. Обновляется только затронутый снимок с просмотром результата; эталон не заменяет проверку перехода.

Сценарии на физических устройствах и со вспомогательными технологиями выполняются по [MANUAL_REGRESSION](../operations/MANUAL_REGRESSION.md) и [PWA_INSTALLATION](../operations/PWA_INSTALLATION.md). Их результаты записываются в Issue/PR, не в эту памятку.

## Воспроизводимая проверка производительности

`npm.cmd run test:performance` генерирует синтетические данные, собирает production и запускает [performance.e2e.ts](../../e2e/performance.e2e.ts):

- Chromium, экран Pixel 5;
- задержка сети 150 мс, загрузка 1,6 Мбит/с, отдача 750 Кбит/с;
- замедление CPU в четыре раза;
- три независимых контекста, сравнение по медиане;
- первый и повторный запуск «Сегодня», переход к заполненному месяцу, отложенная загрузка ECharts.

JSON отдельных прогонов и порогов прикладывается к отчёту Playwright. Численные бюджеты определяет тест. При падении сравниваются прогоны и ресурсы в одинаковом профиле; бюджет не повышается для скрытия регрессии. Синтетический результат не считается замером физического телефона.

Фактические измерения, commit, устройство, сеть и вывод сохраняются в задаче проверки или CI. Для диагностики облака измеряются размер снимка, длительность serialization/merge/sync и трафик без содержимого записей. Один медленный прогон не является основанием менять архитектуру хранения.
