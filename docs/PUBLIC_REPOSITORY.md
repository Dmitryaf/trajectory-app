# Граница публичного репозитория

Этот документ описывает подготовку проекта к публикации. Пока репозиторий приватный, внутренние материалы остаются доступными локально и в приватной истории.

## Что может быть публичным

- исходный код приложения, миграции без секретов и тесты;
- краткий продуктовый `README.md` без внутренних планов и личного контекста;
- `.env.example` только с названиями переменных;
- лицензия, `SECURITY.md`, публичная инструкция запуска и участия в разработке;
- обезличенные демонстрационные данные, прошедшие отдельную проверку.

## Что остаётся внутренним

- `docs/AGENTS.md` и `docs/agent/`;
- `docs/BACKLOG.md`, аудиты, продуктовые гипотезы и рабочие правила;
- внутренняя схема поставки, архитектурная кухня и заметки о будущих изменениях;
- `BACKEND_AUTH_CI.md` и другие временные инструкции по настройке окружений;
- реальные пользовательские данные, адреса аккаунтов, снимки базы, логи и секреты.

Внутренние документы после очистки хранятся локально в игнорируемом каталоге. Публичный `README.md` не должен ссылаться на них.

## Процедура перед публикацией

1. Создать проверенную резервную копию репозитория и внутренних документов.
2. Проверить текущие файлы и всю достижимую историю на секреты, личные данные и внутренние пути.
3. Сформировать точный список удаляемых путей. Не считать удаление файла из текущей ветки очисткой истории.
4. Переписать историю отдельной согласованной операцией и восстановить внутренние документы как локальные ignored-файлы.
5. Проверить `git ls-files`, `git log --all -- <paths>` и `git rev-list --objects --all` для каждого удалённого пути.
6. Проверить недостижимые объекты, заменить найденные ключи и только после этого выполнять force-push.
7. Просмотреть публичный репозиторий как внешний пользователь: README, Issues, Actions, deployments, releases и переменные окружения.

Переписывание истории и force-push выполняются только после отдельного явного разрешения владельца.
