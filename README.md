# Траектория

«Траектория» помогает принимать небольшие решения по своим записям. Вы коротко отмечаете несколько дней, затем сравниваете их и выбираете, что оставить, изменить или проверить дальше. Не нужно заполнять все поля или давать дню общую оценку.

Это рабочая PWA-версия с личным входом, локальным кэшем и облачной копией через Supabase. Её можно открыть в браузере, установить на телефон или компьютер и использовать как личный трекер действий, состояния и условий дня.

## Как пользоваться

1. В разделе «Сегодня» запишите несколько важных фактов.
2. В конце недели посмотрите, что повторялось и что стоит изменить.
3. В конце месяца сравните недели, события и полученные результаты.
4. В «Трендах» сравнивайте несколько месяцев, когда записей станет достаточно.
5. В Журнале отдельно сохраняйте завершённые результаты, важные события и мысли.
6. В Эксперименте можно попробовать одно изменение несколько дней или недель и потом записать, что вы заметили.

## Возможности

- сон, время отбоя и подъёма, качество сна и энергия;
- автоматический расчёт времени в кровати и оценка регулярности режима;
- сон и состояние следующего дня;
- независимый контекст дня с настраиваемыми условиями вроде позднего отхода ко сну, новостей, нагрузки или шума;
- отметка особого дня: болезнь, поездка, перегруз, событие или восстановление;
- действия, связанные с работой или её поиском;
- действия по текущей цели: конкретное действие, подготовка, поддержание, восстановление или другие занятия;
- личное определение текущей цели и того, что считается конкретным действием с заметным результатом;
- бокс, бачата и другая активность;
- питание относительно заранее заданного критерия, короткий контекст и опциональный вес;
- присутствие выбранных личных областей: семьи, чтения, творчества, отдыха или своих пунктов;
- необязательный блок работы с общими и своими вариантами, например «Смена», «Урок» или «Собеседование»;
- отдельный журнал важных событий, решений, жизненных изменений и мыслей;
- маркеры событий на графиках и сравнение равных периодов до и после;
- отдельный список завершённых итогов;
- редактирование важных событий и итогов;
- недельная тепловая карта и короткий обзор;
- проверка решения, принятого на прошлой неделе;
- план «если-то» для одного конкретного изменения следующей недели;
- сохраняемые недельный и месячный обзоры условий, решений и следующей цели;
- напоминания в конце недели и месяца о разборе периода;
- статистика и локальный анализ за 3, 6 и 12 месяцев с учётом полноты данных;
- календарная карта качества заполнения без серий и оценок;
- общая хронология событий, решений недель и месяцев, их проверки и итогов;
- локальные подсказки для разбора недели и месяца;
- ручная выгрузка готового промпта и JSON для анализа во внешней нейросети без отправки данных самим приложением;
- автоматические наблюдения по связи сна, энергии и физической активности;
- сравнение повторяющихся факторов с обычными днями без них, без причинных заявлений;
- отдельная базовая статистика обычных и особых дней;
- месячная динамика сна, регулярности, веса, областей жизни и итогов;
- один временный эксперимент: выбранное изменение, ежедневная отметка и собственный итог;
- локальный IndexedDB-кэш, облачная копия Supabase и JSON-резервные копии;
- установка как PWA и работа без сети.

## Запуск

```bash
npm install
npm run dev
```

Изолированные состояния переиспользуемых компонентов:

```bash
npm run storybook
```

После запуска открой адрес, который покажет терминал (обычно `http://localhost:5173`).

Для закрытой беты встроенная форма обратной связи включается переменной `VITE_FEEDBACK_ENABLED=true`. Сообщение отправляет Vercel Function: получатель и ключ почтового сервиса остаются в server-side переменных и не попадают в браузер. Настройка и полная граница готовности к приглашениям описаны в [BETA_RELEASE.md](./docs/operations/BETA_RELEASE.md).

Проверка:

```bash
npm run check
```

Отдельные read-only проверки кода и форматирования, а также явные команды исправления:

```bash
npm run lint
npm run format:check
npm run lint:fix
npm run format
```

`lint:fix` и `format` меняют файлы и запускаются только явно. `npm run check`, CI и pre-commit ничего не форматируют автоматически.

Первый запуск реальных браузерных сценариев требует локального Chromium Playwright:

```bash
npx playwright install chromium
npm run test:e2e
```

Для разработки используется Node.js 22. После `npm install` Husky подключает проверки: перед коммитом запускаются тесты и сборка, а сообщение коммита проверяется по Conventional Commits (`feat: ...`, `fix: ...`, `docs: ...`). Полные правила находятся в [docs/agent/QUALITY.md](./docs/agent/QUALITY.md).

## Хранение данных

Данные сначала сохраняются в IndexedDB текущего браузера, а затем приложение пытается обновить облачную копию Supabase для текущего пользователя. IndexedDB остаётся локальным кэшем и защитой от временной недоступности сети.

Если облако недоступно, изменения остаются локально и помечаются как ожидающие синхронизации. Если локальная копия и облачная копия расходятся и приложение не может безопасно выбрать сторону, оно показывает конфликт и просит вручную выбрать действие в настройках.

JSON-экспорт в настройках остаётся ручной страховкой перед восстановлением из облака или очисткой данных.
