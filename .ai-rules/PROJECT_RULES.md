# Правила проекта «Траектория»

Общие правила подключены через [RULESET](RULESET.md). Здесь только устойчивая специфика; текущие приоритеты и отложенные направления ведутся в [GitHub Project](https://github.com/users/Dmitryaf/projects/1) и [Issues](https://github.com/Dmitryaf/trajectory-app/issues).

## Инварианты

- PWA помогает увидеть фактическое наполнение периода; ежедневный ввод и решение что-либо менять необязательны. Нет общей оценки человека или дня.
- Не терять, не смешивать и не подменять личные данные. Отсутствие, неизвестное и явно пустой ответ различаются.
- Сохранять совместимость IndexedDB, JSON-резервных копий и облачных снимков. Изменение модели проверяется через нормализацию, store, backup/cloud, экспорт и затронутую аналитику.
- При обязательной авторизации отсутствие backend-конфигурации закрывает приложение безопасным экраном. Привилегированные ключи не попадают во frontend; облачные строки изолированы RLS.
- Код развивается вертикальными сценариями. Новые route views остаются тонкими адаптерами; общая абстракция требует реальных повторных потребителей.

## Граница публикации

Репозиторий публичный. Документация в Git должна помогать пользователю, разработчику или оператору работать с текущей системой. Секреты, реальные записи, токены, логи, снимки базы, личный контекст и внутренние исследовательские материалы не публикуются.

Рабочие приоритеты и результаты проверок остаются в Project/Issues/PR с учётом их видимости; закрытый материал не становится публичным из-за ссылки на задачу. Отдельный Markdown-backlog и второй framework инструкций не создаются. История решений доступна через Git, Issues и PR.

## Проверки

- Код или конфигурация: `npm.cmd run check`, `git diff --check`, `git status --short`.
- UI: дополнительно целевой Playwright-сценарий для затронутых состояний и ширин. Общий каркас, навигация, адаптивные правила, закреплённые элементы или раскладка условных блоков требуют полного `npm.cmd run test:e2e`.
- Clipboard/Download API, маршруты, авторизация и облачная сверка также требуют полного `npm.cmd run test:e2e`.
- Только Markdown: формат изменённых файлов, ссылки, `git diff --check` и `git status --short`. Frontend gate без изменений кода, конфигурации или зависимостей не требуется.
- После изменения manifest, lock или состава AI Rules: `ai-rules.ps1 doctor`, `status` и read-only `plan`. Managed snapshot вручную не меняется.
- Перед staging/production: полный E2E и профильная ручная приёмка по [DELIVERY](../docs/operations/DELIVERY.md). Зелёный CI не заменяет проверку эффекта, который он не наблюдает.

## Изменения и Git

Для продуктовой функции до реализации определить пользовательскую пользу, период, необязательность, место в обзоре/экспорте и запрещённые выводы. При миграции пользовательского варианта заранее определить судьбу старых записей и защитить преобразование тестом.

Сообщения коммитов — английские Conventional Commits. Роли веток, merge-стратегия и hotfix-путь определяются только [DELIVERY](../docs/operations/DELIVERY.md).
